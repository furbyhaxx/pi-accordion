## Ranked findings

1. **Account for task notices on the actual wire** | `core/wire.ts:217-219`; `extension/accordion.ts:3571-3589` | **Verified by reading.** Notices are custom messages: Pi sends their content to the model as user messages (`node_modules/@earendil-works/pi-coding-agent/dist/core/messages.js:89-95`), but Accordion creates no corresponding blocks. Repeated waiting, edit and resume notes therefore survive folding while escaping token accounting, recall and transcript dumps. **Change:** ingest model-visible custom content into Truth and give obsolete notices an expiry policy.

2. **Bound accumulated history, not just individual records** | `conductors/in-process/taskfold/records.ts:138-150`; `conductors/in-process/taskfold/taskfold.ts:909-924` | **Verified by reading; sizes are estimates.** History preserves the entire outcome, and condensation explicitly skips existing history. For 300 independent roots with 60-character titles, representative 200-character outcomes occupy approximately **25,425 tokens**; maximum 2,000-character outcomes occupy **160,425 tokens**, before pins and other context. No further decay exists. **Change:** introduce a globally budgeted, recallable older-history index with shorter standing entries.

3. **Preserve navigable recovery below direct children** | `conductors/in-process/taskfold/records.ts:141`; `conductors/in-process/taskfold/taskfold.ts:1194-1196` | **Verified by reading.** Root history prints only direct-child tags, then compilation discards handles whose tags disappeared. In a three-level tree, recalling a surviving child report cannot expose its grandchildren’s codes; `core/recallView.ts:227-231` prints “(no code)”. Raw content remains searchable, but task-by-task navigation breaks precisely as larger trees finish. **Change:** retain descendant addresses through a paginated task-directory mechanism rather than requiring every address in the standing carrier.

4. **Page large task reports instead of permanently cutting them** | `core/recallView.ts:207-238` | **Verified by reading.** Reports enumerate every direct subtask, then truncate at the call limit. The report renderer never receives `page`, so asking for page 2 repeats the same prefix. Three hundred children with titles and 160-character outcomes readily exceed the approximately 31,400-character page. **Change:** paginate report sections and subtask rows with explicit continuation calls.

5. **Provide pressure relief for fragmented untracked work** | `conductors/in-process/taskfold/taskfold.ts:1013-1042` | **Verified by reading.** Untracked folding is **enabled by default**, but requires eight qualifying assistant messages in one uninterrupted run. User messages and Markdown/text reads break runs and remain ineligible. Thousands of short exchanges or document-heavy exploration can therefore accumulate despite the backstop. `floor` defaults to false (`:73`). Native compaction is the eventual default overflow escape (`extension/accordion.ts:3898-3902`), not indefinite recoverable folding. **Change:** fold completed short runs collectively under pressure, including recoverable document reads, while retaining user instructions.

6. **Stop materializing the archive repeatedly for bounded searches** | `core/recallView.ts:155-166,365-386`; `core/agentView.ts:180-203` | **Suspected latency problem; algorithm verified by reading.** Archive search resolves every fold separately; each resolution scans groups and blocks and joins full raw text that `sourceOf` then discards. Query matching and excerpt construction also run over every candidate before selecting a page. Pagination repeats this work. At more than 1M transcript tokens, an 8k-token response does not imply bounded retrieval cost. **Change:** index code-to-members and searchable entries by Truth revision; resolve metadata without constructing whole transcripts.

7. **Send bounded resume orientation instead of the entire task tree** | `extension/taskBinding.ts:107-126`; `extension/tasks.ts:1039-1046` | **Verified by reading.** A changed resumed list or UI attachment invokes `renderList`, including all finished tasks. Three hundred 60-character titles alone contribute 18,000 characters—about **4,500 estimated tokens**, excluding identifiers and annotations. Each subsequent changed resume adds another outline; finding 1 makes these especially persistent. **Change:** send counts, active branch, blocks, next task and changed IDs; offer paginated historical browsing.

8. **Replace one-shot missing-task coaching with bounded recurrence** | `extension/taskCoach.ts:147-153,270-279` | **Verified by reading.** After the orientation allowance, missing-list and missing-leaf coaching each speak once per prompt. An autonomous run can then perform thousands more untracked calls silently. Gate mode similarly fails open for the remainder of the run after its configured refusals. Existing evaluation records only **76/135 tracked results, 56%**, against the 95% target of the reliability plan at the time. **Change:** recheck after a bounded amount of additional work, with concise escalation rather than repeating the full protocol.

9. **Keep span-size and pressure warnings active in gate mode** | `extension/taskCoach.ts:257-266` | **Verified by reading.** Every mode except `coach` immediately takes the counting-only path. Gate mode therefore suppresses both large-leaf reminders and notices that pressure folding changed the current task’s context. Conversely, coach mode repeats large-leaf prose every ten work increments indefinitely (`:205-211`). **Change:** separate tracking enforcement from span-health notifications; emit short, state-change-based warnings in both modes.

10. **Keep “reveal hidden tasks” within the widget’s row budget** | `extension/tui/taskWidget.ts:220-224`; `extension/tui/taskTree.ts:217-247` | **Verified by reading; live appearance unverified.** Clicking a hidden sibling row reveals every represented ID permanently for that widget instance. Revealed IDs bypass the row budget, so one click on hundreds of finished siblings can produce hundreds of above-editor rows. **Change:** reveal a bounded page or open the full Tasks panel instead.

11. **Cache task-tree construction, not only transcript adaptation** | `extension/tui/taskViews.ts:473-486,554-556,673-675`; `extension/tui/taskTranscript.ts:243-265` | **Suspected latency problem; repeated work verified by reading.** Rendering and navigation reconstruct the session tree. Each task’s token calculation filters the transcript again; 300 tasks over 10,000 blocks means roughly three million block visits just for those per-task passes, before other construction. **Change:** cache structural nodes and per-span charges by transcript revision; refresh elapsed-time labels separately.

12. **Budget background fact extraction across the session** | `extension/accordion.ts:4792-4815`; `core/factLedger.ts:27-33,79` | **Verified by reading; cost estimates are bounds.** Default-enabled extraction has per-task caps but no session cost cap. Three hundred eligible tasks can generate **300–1,200 side-model calls**; four near-full chunks per task approach **28.8M input tokens**. Parents reread descendants already processed as children. **Change:** extract newly covered entries once, reuse child ledgers, and expose a session-wide extraction budget and progress.

13. **Offer a genuinely compact transcript export** | `extension/tui/transcriptDump.ts:221-225,281-283` | **Verified by reading; user impact unverified live.** Every format includes full task-list metadata, group membership and block details, even the default tree export. Three hundred reports at their combined 26,000-character report-field limit contribute approximately **7.8M characters of report text alone**, despite a much smaller outgoing projection. **Change:** offer wire-only/summary-metadata exports while retaining the existing full-fidelity option.

## First three changes

1. Put model-visible notices into authoritative accounting and expiry.
2. Add globally bounded older-history storage with complete, paginated task-address navigation.
3. Strengthen recoverable pressure relief for fragmented untracked work before native compaction becomes necessary.
